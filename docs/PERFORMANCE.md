# 性能测量方法与限制

本报告使用独立 Windows 发布 EXE，在本机 NVIDIA GeForce RTX 4050 Laptop GPU 上运行。场景脚本按固定顺序在七个区域各停留10秒，前2秒预热，后8秒记录真实进程时钟的逐帧间隔。敌人、生存、天气、照明与默认阴影继续运行；场景转换采用测试传送，不代表人工游玩或加载路线。

测试顺序：海岸、森林、暴风雨湿地、工业区、仓库室内、高地、夜间营地。VSync关闭，仅基准入口将内部渲染固定为1920×1080；不自动修改玩家设置文件。tools/benchmark.ps1 校验实际渲染纹理尺寸，并保存 JSON 与日志。

测量前确认并关闭了早期开启的隐藏测试进程3468。其他用户应用未关闭；不是干净环境性能验收。

## 校准发现

- 初次只记录逻辑 UI 尺寸1280×720，不能用它推断实际渲染尺寸。
- 增加窗口与纹理尺寸记录后，确认150% DPI环境下请求1920×1080窗口会生成2880×1620纹理。该批数据保留在 benchmark-hidpi-2880.json，不冒充1080p结果。
- 改为在基准入口使用固定内部视口，并在运行前检查实际纹理为1920×1080；不满足时立即失败。
- 早期脚本按引擎dt统计，现改用真实帧间隔。两种结果不可直接用于优化前后百分比比较。
- 发布构建的 Godot 静态内存统计返回0，因此没有把0视为真实内存占用，也未给出内存结论。

## 优化内容

HUD 每次先生成完整文本，只在内容改变时提交一次，避免每个物理帧连续设置多次标签文本。天空颜色参数改为每0.5秒更新，保留昼夜变化；太阳与角色运动仍按正常物理帧运行。短音效每批采样只读取一次系统时钟，减少逐采样计时调用。

这些改动没有降低贴图分辨率、世界内容或默认阴影。由于校准期间测量方法发生变化，不能给出可靠的优化提升百分比。

最终1080p分区域结果将以通过尺寸校验的 benchmark-optimized1080.json 为依据。短时区域采样不能替代两次45分钟游玩、最差情况压力测试、低配机器和干净环境验收。

## 已验证的1080p短测

2026-11-23，发布 EXE。窗口1920×1080、内部纹理1920×1080，逻辑视口也为1920×1080；检查通过。数据源 build/benchmark-optimized1080.json，日志 build/benchmark-optimized1080.log。

| 场景 | 平均 FPS | 95% 帧间隔 ms | 最大帧间隔 ms |
| --- | ---: | ---: | ---: |
| 海岸 | 323.69 | 6.30 | 13.48 |
| 森林 | 150.05 | 9.90 | 23.53 |
| 暴风雨湿地 | 328.54 | 6.41 | 13.05 |
| 工业区 | 179.97 | 8.29 | 18.69 |
| 仓库室内 | 169.65 | 9.27 | 19.34 |
| 高地 | 477.81 | 5.45 | 30.92 |
| 夜间营地 | 289.14 | 6.34 | 13.02 |

场景内平均值不等于整局平均，最大帧间隔不等于长期最坏卡顿。湿地测试中实际敌人攻击降低了角色生命，但没有死亡切换；其余场景没有出现死亡。森林与工业区仍有较多绘制调用（约2347和2554），值得继续做实例化、模型层级和可见范围优化。没有据此给出最低推荐配置。

玩家窗口设置目前使用逻辑窗口尺寸，受系统 DPI 影响，不能把菜单分辨率选项直接当作内部渲染尺寸。本基准通过独立入口强制内部1080p；普通窗口模式的分辨率呈现仍需进一步统一。
